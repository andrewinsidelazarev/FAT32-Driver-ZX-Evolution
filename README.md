# Самостоятельный FAT32 для Z80

Драйвер извлечён из исправленного CORE32
[Wild Commander Improved](https://github.com/andrewinsidelazarev/Wild-Commander-Improved) и собирается
отдельно. Первый потребитель —
[ZiFi SPG](https://github.com/andrewinsidelazarev/ZiFi-ESP32-S3-Zero/tree/main/ZiFi%20SPG)
(`zifi.spg`) из репозитория ZiFi-ESP32-S3-Zero; подключение описано в его
[FAT32.md](https://github.com/andrewinsidelazarev/ZiFi-ESP32-S3-Zero/blob/main/ZiFi%20SPG/FAT32.md).
Исходный снимок WC — commit
[`c98c4f5`](https://github.com/andrewinsidelazarev/Wild-Commander-Improved/tree/c98c4f575c0f2d25b464f4568e592607713e2e76);
он и SHA-256 файлов снимка записаны в `upstream/manifest.json`.
Обычная сборка использует только `src/`, `include/` и `ports/` этого проекта.
Комментарии и документация — UTF-8.

## Сборка

Нужны Python 3 и sjasmplus. Можно задать полный путь в `SJASMPLUS`; также
проверяются `C:\z80\zuma\sjasmplus.exe` и `PATH`.

```powershell
python build.py
```

Результаты в `build/`: `fat32.bin`, `fat32-work.bin`, `port_sdzc.bin`, листинги,
символы и `manifest.json` с размерами и SHA-256 исходников и образов.
Для пересборки ZiFi запустить его `build.bat`: он сначала собирает драйвер,
затем копирует образы и помещает их в `build/zifi.spg`. По умолчанию требуется
соседняя папка `FAT32 Driver`; другой путь задаётся через `FAT32_DRIVER_DIR`.
`tools/import_wc.py` и `tools/integrate_zifi.py` — исторические однократные
операции переноса, в сборке не участвуют. Их повторный запуск для обновления
драйвера не нужен.

## Память и подключение

| Адрес Z80 | Назначение |
| --- | --- |
| `#0000..#3FFF` | Отдельная рабочая RAM: каталоги, буферы, состояние, адаптер |
| `#3900` | Таблица четырёх обработчиков SD-ZC внутри рабочей RAM |
| `#4000..#7FFF` | Код и внутреннее состояние драйвера в RAM |
| `#4000..#417F` | 128 фиксированных входов по три байта: `JP обработчик` |
| `#8000..#BFFF` | Код приложения, стек, имена и блок параметров FILEX |
| `#C000..#FFFF` | Окно данных приложения, в том числе сменяемые страницы |

Ядро не переключает банки и не обращается к портам конкретного компьютера.
Текущий порт `ports/sdzc.asm` реализует SDHC/SDSC/MMC через `#57/#77`, без DMA.
Другой накопитель подключается своей таблицей `init/read512/write512/sync`.
Во время вызова окна драйвера, приложения и стека должны оставаться доступны.
Код самомодифицирующийся; размещать его в ROM нельзя. Один экземпляр содержит
один том, текущий каталог и контекст одного выбранного файла. Повторный вход
из прерывания и одновременные вызовы одного экземпляра не поддерживаются.

Таблица устройства — четыре слова с адресами обработчиков. `init` получает
`A=номер устройства`; `read512/write512` получают `DE:HL=абсолютный LBA`,
`BC=адрес 512-байтового буфера`; `sync` завершает ожидающие операции устройства.
Результат обработчиков: `A=0` — успех, иначе код ошибки. Они сохраняют `IX`,
`IY` и альтернативные регистры; основные пары может менять сам адаптер.
Обработчики должны быть доступны при отображении рабочих окон драйвера.

```asm
        INCLUDE "fat32.inc"
        ; Приложение уже отобразило рабочую RAM и код драйвера.
        LD HL,#3900
        XOR A
        CALL FAT32_BIND
        CALL FAT32_DEVICE_INIT
        JP NZ,error
        CALL FAT32_MOUNT
        JP NZ,error
        LD HL,file_spec
        CALL FAT32_CREATE
        JP NZ,error
        LD HL,#C000,BC,1234
        CALL FAT32_APPEND
        JP NZ,error
        CALL FAT32_CLOSE
        JP NZ,error
        ; ...
file_spec: DB #20,0,0,0,0,"example.bin",0
```

## API версии 1

Адрес любого входа — `#4000 + номер*3`; адрес обработчика внутри `JP` может
меняться при пересборке. Приложение использует константы `include/fat32.inc`.

| Номер | Операция |
| --- | --- |
| 0, 9 | Подключить таблицу устройства: `HL=таблица`, `A=устройство` |
| 1 | Инициализировать устройство; прежний том и файл становятся неактивными |
| 2 | Информация: `A=версия`, `BC=число входов`, `DE=размер кода`, `HL=описатель` |
| 3 | Найти и смонтировать FAT32 (MBR/поддерживаемая цепочка EBR либо том от LBA 0) |
| 4, 5 | Низкоуровневый обмен секторами (`RDD/SDD`) |
| 6 | Позиционирование по кластеру (`GIPAG`) |
| 7, 48 | Читать сектора выбранного файла: `HL=буфер`, `B=число секторов` |
| 8, 49 | Записать выделенные сектора файла; размер и цепочку не увеличивает |
| 10, 11 | Установить/получить кластер текущего каталога (`GLSTCAT/TLSTCAT`) |
| 12, 14 | Поиск свободного кластера / выделение цепочки (`SRHFCL/MKSG`) |
| 13, 76 | APPEND: дописать `BC` байтов из `HL`, зафиксировать точный размер |
| 15, 77 | FILEX: `HL=32-байтовый блок параметров` |
| 16..18 | Подсказка свободного места, получение/копирование записи (`RFRH/GENTRY/TENTRY`) |
| 19, 72 | Создать файл: `HL -> [атрибут, размер32 LE, имя, 0]` |
| 20, 73 | Создать каталог: `HL -> [имя, 0]` |
| 21, 75 | Удалить по имени: `HL -> [флаг, имя, 0]` |
| 22, 74 | Переименовать: `HL -> [флаг, старое имя, 0]`, `DE -> [новое имя, 0]` |
| 23, 24 | Освободить цепочку / кластер в сектор (`DLSG/CHTOSE`) |
| 26, 59 | Найти и выбрать запись: `HL -> [флаг, имя, 0]` |
| 27, 60 | Чтение с видеораскладкой: 256 байтов строки с шагом 512 (`LOAD256`) |
| 28, 61 | Пропуск секторов (`LOADNON`) |
| 29, 30, 58 | Итераторы каталога (`NXTETY/NXTETY2`) |
| 31, 56, 63 | Войти в выбранный каталог |
| 32 | Перейти в корень |
| 33, 50, 62 | Вернуться к началу выбранного файла; `OPEN` следует за `FIND` |
| 34, 35 | Синхронизация / синхронизация и закрытие выбранного файла |
| 36 | Смонтировать том с заданного `DE:HL=LBA` |
| 51, 52 | Дополнительные входы `TENTRY/CHTOSE` |
| 25, 37..47, 53..55, 57, 64..71 | Неподдерживаемые позиции, включая операции интерфейса WC |
| 78..127 | 50 зарезервированных `JP` для будущих команд |

Неподдерживаемая команда возвращает `A=#FE`, `NZ`, `CF=1`.
Высокоуровневые операции, кроме `FIND` и `INFO`, возвращают `A=0/Z` при успехе.
Для `FIND`: `CF=1` — ошибка; `CF=0/Z` — не найдено; `CF=0/NZ` — найдено,
размер в `DE:HL`. Ошибки APPEND/FILEX следует проверять по `A/NZ`, одного
`CF` недостаточно. При секторном чтении `A=#0F`, `NZ`, `CF=0` может означать
нормальный конец цепочки после уже переданных данных; ошибка обмена даёт `CF=1`.
Поле длины файла и число фактически читаемых байтов приложение учитывает само.

APPEND принимает от 0 до 16384 байтов, буфер целиком в `#8000..#FFFF`.
Конец ровно `#10000` допустим. FILEX-блок целиком лежит в `#8000..#BFFF`,
данные — в `#8000..#FFFF`, без наложения на блок параметров, код и стек.
Буфер должен оставаться отображённым до возврата. Имена используют принятую
в WC однобайтовую кодировку CP866 с LFN на диске; это не UTF-8 API имён.

Низкоуровневые команды сохраняют контракты CORE32, описанные в `upstream/`;
они требуют смонтированного тома, правильных указателей и состояния итератора.
В частности, старый `DELETE` не проверяет пустоту каталога: вызывающий код
обязан проверить её до удаления. Это не рекурсивное удаление дерева.

FILEX реализует все восемь операций: возможности, чтение/запись по 32-битовому
смещению, изменение EOF, сведения о ФС, перенос/переименование, метаданные,
чтение FAT. Формат блока, флаги, статусы и маска возможностей `#FF` описаны в
`include/filex.inc`. `QUERY_CAPS` доступен до подключения устройства.

При недействительной сигнатуре FSInfo или ссылке за пределы зарезервированной
области драйвер пропускает обновление подсказок. Такой сектор не переписывается;
поиск свободного места выполняется по FAT. Основание: FSInfo хранит последнюю
оценку числа свободных кластеров и подсказку начала поиска; оба значения
требуют проверки ([спецификация Microsoft FAT32 1.03, стр. 21–22](https://www.cs.fsu.edu/~cop4610t/assignments/project3/spec/fatspec.pdf)).
Пропуск неверной подсказки — выбранная политика этого драйвера. Ошибка
секторного обмена при обновлении корректного FSInfo остаётся ошибкой операции.

## Поиск тома

`MOUNT` читает сектор 0 и берёт первую запись MBR с типом `#05`, `#0B`, `#0C`
или `#0F`. Если по этому адресу лежит годный BPB, том смонтирован. Иначе адрес
считается началом первого EBR и начинается обход расширенного раздела: у
каждого EBR проверяется его логический том (смещение отсчитывается от самого
EBR), а ссылка на следующий EBR — от начала первого. Обход ограничен исходной
глубиной `COUNT=3`, то есть проверяются два логических тома; если годного BPB
не нашлось, драйвер пробует смонтировать том прямо с LBA 0.

В исходном коде WC база обхода не инициализировалась: он повторно читал сектор
0 вместо EBR, и логический том в расширенном разделе не находился никогда.
Исправлено; покрыто тестом `test_volume_inside_extended_partition_chain`.

### Требования к тому

`MOUNT` принимает только `BPB_BytsPerSec = 512`; любое другое значение —
отказ монтирования (`A=#01`, `CF=1`). Порт SD-ZC задаёт карте длину блока 512
командой CMD16, для SDHC/SDXC она фиксирована.

Число копий FAT и `BPB_ExtFlags` читаются из тома: при выключенном
зеркалировании (бит 7) обновляется только активная копия, иначе — все
`BPB_NumFATs`. Том с одной FAT работает; активная копия, номер которой не
меньше числа копий, отвергается при монтировании.

## Интеграция ZiFi

[`zifi.spg`](https://github.com/andrewinsidelazarev/ZiFi-ESP32-S3-Zero/tree/main/ZiFi%20SPG) содержит код драйвера на странице `#0E`,
рабочую RAM с SD-ZC на `#0F`.
`fat32_adapter.asm` сохраняет и восстанавливает банки 0, 1, 3 и режим
обработки интерфейса из прерываний. Музыка может продолжать играть; переход
к следующему треку откладывается до выхода из драйвера.

Через новый драйвер читается `zifi/zifi.ini` (до 511 байтов плюс ноль),
создаются `zifi/downloads/YYYY-MM-DD`, сохраняются загрузки до 640 КиБ.
Диапазон источника проверяется до создания файла. APPEND вызывается частями
по границам страниц 16 КиБ, точный размер обновляется после каждой части.
Новый файл создаётся под своим именем. Если имя уже занято, перезапись
транзакционная: загрузка пишется во временный `ZIFITMP.$$`, и только после
успешного закрытия прежний файл удаляется, а временный получает его имя.
При ошибке появляется сообщение `SD save failed; file may be partial`, и
последующее действие с загрузкой отменяется. У нового файла на диске остаётся
уже записанная часть; при замене прежний файл остаётся цел, а недописанный
`ZIFITMP.$$` удаляется при следующей замене в том же каталоге. Покрыто
тестами `test_paged_save_maximum_and_replace` и
`test_failed_replace_keeps_previous_file`.

## Проверки и границы

```powershell
python -m pip install -r requirements-test.txt
python -B -m unittest discover -s tests -v
```

Перед тестами интеграции требуется свежая сборка ZiFi. Тесты выполняют
собранные инструкции Z80; файловая система проверяется независимым разбором
MBR/BPB, каталогов, LFN, FAT-цепочек, зеркал FAT и содержимого файлов.
Отдельно проверяются секторные callbacks, SPI и отложенный байт порта
Z-Controller, банки ZiFi, чтение INI, отказ записи и музыкальное прерывание.
Модель не заменяет реальную SD-карту и проверку на ZX-Evolution.

Для Unreal есть `tests/unreal_smoke.asm` и `tools/prepare_unreal.py`.
Они работают с **копией** IMG в `build/unreal/`. В исходной SD-модели Unreal
обнаружена ошибка: `TSdCard::Wr` при пустом байте в `ST_IDLE` возвращает старое
`NextState`, снова выдавая ответ CMD24. `tools/build_unreal_test.py` собирает
отдельный эмулятор с локальным исправлением `break` на `return`; исходная
установка и исходники эмулятора не изменяются. Результат такого запуска
нужно указывать именно как проверку в исправленной тестовой копии Unreal.

FAT32 не имеет журнала транзакций. Обработка возвращаемых ошибок и откат
проверенных отказов не обеспечивают атомарность при отключении питания,
извлечении карты или потере уже подтверждённых записей её контроллером.
Результаты сборки и моделей не являются подтверждением работы на физическом
ZX-Evolution. Текущий результат проверки фиксируется в `VALIDATION.md`.
